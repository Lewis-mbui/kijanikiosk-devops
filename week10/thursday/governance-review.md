## Governance Review

| Control                                  | Pass / Fail | Finding                                                                                                                                                                                                                                                                | Specific Remediation                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **1. Least privilege**                   | **Fail**    | The `receipts_processor_policy` grants `s3:*` against `Resource = ["*"]`. The Lambda therefore receives every S3 action against every S3 resource accessible through the account rather than only the permissions required to process receipt objects.                 | Replace `Action = ["s3:*"]` with only the required operations, such as `s3:GetObject` and, only if required, `s3:PutObject`. Replace `Resource = ["*"]` with `"${aws_s3_bucket.payment_receipts.arn}/*"` so permissions are scoped to receipt objects in the intended bucket.                                                                                                                                      |
| **2. Encryption at rest and in transit** | **Fail**    | The payment-receipts bucket has no explicit server-side encryption configuration. The module also contains no bucket policy enforcing secure transport when objects are accessed.                                                                                      | Add an `aws_s3_bucket_server_side_encryption_configuration` resource for `aws_s3_bucket.payment_receipts`, using `AES256` or an organisation-approved KMS key. Add an `aws_s3_bucket_policy` that denies S3 operations when `aws:SecureTransport` is `"false"` so clients must use TLS.                                                                                                                            |
| **3. No hardcoded secrets**              | **Fail**    | `DB_PASSWORD = "kijani-prod-password-2024"` embeds a production database credential directly in the Terraform source. If committed, the credential could be exposed through Git history, pull requests and other systems that handle the Terraform code.               | Change the Lambda environment value to `DB_PASSWORD = var.db_password`. Add `variable "db_password" { type = string, sensitive = true }` to `variables.tf`. Supply the value from an approved external secret source such as AWS Secrets Manager or, for an appropriate controlled workflow, a `.tfvars` file excluded from Git with `.gitignore`. The plaintext password must not be committed to the repository. |
| **4. Naming and tagging conventions**    | **Fail**    | Resources use generic names such as `my-payment-receipts-bucket`, `receipts-processor-role`, and `receipt-processor`. The resources also contain no organisational tags identifying properties such as project, environment, owner, or cost centre.                    | Replace generic names with the KijaniKiosk naming convention and include the deployment environment, for example `kijanikiosk-payment-receipts-${var.environment}`. Apply required tags such as `Project = "KijaniKiosk"`, `Environment = var.environment`, `Owner = "platform-team"`, and `CostCentre = var.cost_centre` to applicable resources.                                                                 |
| **5. Auditability and logging**          | **Fail**    | No S3 access logging, CloudTrail object-level auditing, or equivalent audit configuration is declared for the bucket storing payment receipts. Access to sensitive receipt data would therefore lack the explicit audit controls required by the governance checklist. | Add an `aws_s3_bucket_logging` resource for `aws_s3_bucket.payment_receipts` targeting a dedicated, secured audit-log bucket, with an appropriate prefix such as `payment-receipts/`. Where required by the production policy, configure CloudTrail S3 data events to record object-level operations and retain the resulting logs according to organisational policy.                                             |
| **6. Data classification and residency** | **Fail**    | The AWS provider specifies `region = "us-east-1"`. This places infrastructure holding East African payment-receipt data in a US region without evidence that cross-jurisdictional storage has been reviewed and approved.                                              | Change the provider to the approved region, `af-south-1`. Prefer defining `variable "aws_region" { type = string, default = "af-south-1" }` and setting the provider to `region = var.aws_region`. The deployment workflow should also enforce the approved region for payment-data workloads so an arbitrary region cannot be selected without review.                                                            |
