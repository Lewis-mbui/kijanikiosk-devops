Credential Audit
================

Purpose
-------

This audit verifies that sensitive credentials used by the KijaniKiosk CI pipeline are handled securely and do not appear in the repository, Git history, or Jenkins build output.

Audit Date
----------

Week 5 Friday Capstone

Check 1: Jenkinsfile Credential Review
--------------------------------------

Command:

grep -inE 'password|secret|token|pass' Jenkinsfile \
| grep -vE 'credentialsId|usernamePassword|usernameVariable|passwordVariable|NEXUS_PASS|NEXUS_TOKEN|token from the injected credentials'

Result:

PASS

No literal credential values were found in the Jenkinsfile. The only matches from the initial search were references to Jenkins credential APIs, variable names, and explanatory comments.

----------------------------------------------------------------

Check 2: Repository Files
-------------------------

Command:

git ls-files | grep ".npmrc"

Result:

PASS

No .npmrc file is tracked by Git. Authentication configuration is generated temporarily during the Publish stage and removed before the shell step exits.

----------------------------------------------------------------

Check 3: Git History
--------------------

Command:

git log --all -S"<nexus-password>" --oneline

Result:

PASS

No commits in the repository history contain the Nexus password. Credentials have never been committed to source control.

----------------------------------------------------------------

Check 4: Jenkins Build Log
--------------------------

Method:

Reviewed the console output of a successful pipeline run.

Result:

PASS

Credential values do not appear in the build log. Jenkins injects credentials using the `withCredentials` step and masks sensitive values. The temporary `.npmrc` file is created and deleted within the same shell step, preventing credential leakage.

----------------------------------------------------------------

Overall Assessment
------------------

All credential audit checks passed.

The pipeline follows good credential hygiene by:

- Keeping credentials in the Jenkins Credentials Store rather than the repository.
- Injecting credentials only for the duration of the Publish stage.
- Never committing authentication files to Git.
- Preventing credentials from appearing in Git history or Jenkins build logs.
- Removing temporary authentication files immediately after publishing.
